# 파일 서버 성능 평가 가이드

> **평가의 핵심 질문: 얼마나 큰 파일을, 얼마나 많이, 동시에 처리할 수 있는가?**
>
> 이 문서는 사용자 관점에서 "요청이 성공했는가", "얼마나 빨리 됐는가", "파일이 올바른가"를 기준으로 평가 항목을 정의합니다.
> 서버 내부의 DB lock, CPU, 메모리 등은 평가 대상이 아닙니다.

---

## 평가 대상 엔드포인트

| 엔드포인트 | 역할 |
|---|---|
| `POST /files/upload` | 파일 업로드 |
| `GET /files/{id}/download` | 파일 다운로드 |
| `GET /files` | 파일 목록 조회 |
| `GET /files/folder` | 폴더 내 파일 목록 조회 |
| `POST /files/move-folder` | 폴더 이동 |
| `DELETE /files` | 단일 파일 삭제 |
| `DELETE /files/folder` | 폴더 삭제 |
| `GET /health` | 서버 생존 확인 |

---

## 평가 시나리오

### 시나리오 1. 작은 파일 다수 요청 성능

**목적**: 수백 개의 소형 파일을 동시에 처리할 때 요청 성공률과 응답 속도를 측정한다.

**설정**
- 파일 크기: 100KB ~ 1MB
- 동시 요청 수: 단계적 증가 (50 → 100 → 150)
- 읽기/쓰기 혼합: 업로드 80% + 목록 조회/삭제/폴더이동 20%

**측정 항목**
- 업로드 성공률 (`POST /files/upload`)
- 목록 조회 응답 시간 (`GET /files`, `GET /files/folder`)
- 삭제/이동 성공률 (`DELETE /files`, `POST /files/move-folder`)
- 엔드포인트별 p95 / p99 응답 시간

**합격 기준**

| 항목 | 기준 |
|---|---|
| 업로드 성공률 | ≥ 99% |
| 삭제/이동 성공률 | ≥ 99% |
| 목록 조회 p95 | 안정적 (동시성 증가 시 급등 없을 것) |

---

### 시나리오 2. 큰 파일 다수 요청 성능

**목적**: 수백 MB ~ 1GB 크기의 파일을 다수 동시에 업로드/다운로드할 때 처리량과 성공률을 측정한다.

**설정**
- 파일 크기: 100MB ~ 1GB (랜덤)
- 동시 요청 수: 단계적 증가 (10 → 20 → 40)
- 읽기/쓰기 혼합: 조정 가능 (기본 읽기 80% / 쓰기 20%)

**측정 항목**
- 업로드 처리량 (MiB/s)
- 다운로드 처리량 (MiB/s)
- 전체 처리량 (업로드 + 다운로드 합산, MiB/s)
- 업로드/다운로드 성공률
- 엔드포인트별 p95 / p99 응답 시간

**합격 기준**

| 항목 | 기준 |
|---|---|
| 업로드 성공률 | ≥ 99% |
| 다운로드 성공률 | ≥ 99% |
| 전체 처리량 | 목표 MiB/s 달성 여부 (시나리오별 별도 설정) |
| 동시성 증가 시 처리량 | 선형에 가까운 스케일링 |

---

### 시나리오 3. 큰 단일 파일 요청 성능

**목적**: 한 번에 1GB 이상의 단일 파일을 업로드하거나 다운로드할 때 끝까지 완료되는지를 측정한다.

**설정**
- 파일 크기: 1GB 이상 단일 파일
- 동시 요청 수: 1 (단일 클라이언트)

**측정 항목**
- 업로드 완료 여부 및 소요 시간
- 다운로드 완료 여부 및 소요 시간
- 전송 중 연결 끊김 발생 여부

**합격 기준**

| 항목 | 기준 |
|---|---|
| 업로드 완료 | 성공 (200 응답) |
| 다운로드 완료 | 성공, 파일 끝까지 전송 |
| 전송 중 연결 끊김 | 없을 것 |

---

### 시나리오 4. 파일 무결성 검증

**목적**: 업로드된 파일을 다운로드했을 때 내용이 원본과 동일한지 확인한다. 부하 상황에서도 파일 손상이 없어야 한다.

**설정**
- 파일 크기: 다양 (소형~대형 포함)
- 업로드 직후 동일 파일 다운로드
- 높은 동시 업로드 부하 중에도 포함

**측정 항목**
- 업로드 파일의 체크섬 (SHA256 등)과 다운로드 파일의 체크섬 일치 여부
- 부하 상황에서 체크섬 불일치 발생 횟수

**합격 기준**

| 항목 | 기준 |
|---|---|
| 체크섬 불일치 | **0건** |
| 부하 중 체크섬 불일치 | **0건** |

---

### 시나리오 5. 대용량 파일 스트리밍 성능

**목적**: 대용량 파일 다운로드 시 서버가 파일 전체를 메모리에 올리지 않고 스트리밍으로 전송하는지 확인한다. 느린 클라이언트가 연결을 오래 점유할 때도 다른 요청이 정상 처리되어야 한다.

**설정**
- 준비 파일: 100MB 이상 파일 다수 사전 업로드
- 느린 다운로드 클라이언트: 소량씩 읽으며 sleep → 연결 장기 점유
- 동시 느린 다운로드 수: 단계적 증가 (100 → 200 → 300)
- 병렬 경량 프로브: 느린 클라이언트와 동시에 `GET /health`, `GET /files` 요청

**측정 항목**
- 느린 클라이언트 연결 점유 중 프로브 응답 시간 (부하 전 대비 배율)
- 프로브 성공률
- 503 응답 수 (서비스 거부 신호)
- 다운로드 성공률

**합격 기준**

| 항목 | 기준 |
|---|---|
| 프로브 p95 배율 (부하 전 대비) | ≤ 3.0x |
| 프로브 성공률 | ≥ 95% |
| 503 응답 수 | 0건에 가까울 것 |

---

### 시나리오 6. 동시 동일 파일 접근

**목적**: 동일 파일에 대해 여러 사용자가 동시에 다운로드 요청을 보냈을 때 모두 정상 응답을 받는지 확인한다. 또한 업로드 완료 전 상태의 파일에 대한 접근도 포함한다.

**설정**
- 동일 파일 ID에 대한 동시 다운로드: 10~50 동시 요청
- 업로드 진행 중 동일 경로에 대한 다운로드 시도 포함

**측정 항목**
- 동시 다운로드 성공률
- 각 응답의 파일 무결성 (체크섬 일치 여부)
- 업로드 중 다운로드 시도 시 응답 코드 (404 또는 명확한 오류 코드 반환 여부)

**합격 기준**

| 항목 | 기준 |
|---|---|
| 동시 다운로드 성공률 | ≥ 99% |
| 다운로드된 파일 무결성 | 불일치 0건 |
| 업로드 중 다운로드 응답 | 500 아닌 명확한 오류 코드 (404 등) |

---

## 공통 측정 지표

모든 시나리오에서 아래 지표를 공통으로 측정한다.

| 지표 | 설명 |
|---|---|
| **성공률** | 전체 요청 중 2xx 응답 비율 |
| **p95 응답 시간** | 요청의 95%가 이 시간 이내에 완료됨 |
| **p99 응답 시간** | 요청의 99%가 이 시간 이내에 완료됨 |
| **처리량** | 단위 시간당 전송된 데이터량 (MiB/s) |
| **동시성 내성** | 동시 요청 수 증가 시 성공률과 응답 시간이 안정적으로 유지되는지 |
